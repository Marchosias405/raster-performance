# Performance Analysis of GIS-Style Raster Processing

This project uses synthetic GIS-style raster processing as a workload for studying computer systems performance in C++ on x86-64.

The main goal is to experimentally investigate CMPT 295 concepts including:

- compiler optimization
- compiler-generated assembly
- automatic vectorization
- SIMD/vector instructions
- memory locality and cache behavior
- branch predictability
- input-size effects
- performance measurement

The project is not intended to be a complete GIS application.

## Planned Workloads

The project will use two main operations:

1. 3x3 raster smoothing
2. threshold classification

Multiple implementations and input patterns will be compared where they help demonstrate the systems concepts above.

### 3x3 Smoothing Border Policy

For the smoothing workload, border cells are copied unchanged. Only interior cells are replaced with the average of their 3x3 neighborhood.

### Smoothing Traversal Variants

Two scalar smoothing implementations are currently available:

- row-major traversal: rows are processed first, then columns
- column-major traversal: columns are processed first, then rows

The raster storage itself remains row-major and contiguous in both cases.

The implementations have been verified to produce equivalent output. Their performance and cache behavior have not yet been measured.

## Data

No external dataset is used.

The project uses synthetic GIS-style raster data generated by its own C++ code. The general raster generator is deterministic, so the same dimensions produce the same values.

For each cell, the generator uses its 1D array index:

```text
value = (index % 1000) / 1000.0
```

This produces values from `0.000` through `0.999`, with the pattern repeating every 1000 cells.

Data generation will be performed separately from the timed performance kernels so that dataset creation is not included in kernel timing.

Small hand-created grids will also be used for correctness tests where results should be easy to calculate manually.

## Current Environment

Initial development environment verified on August 6, 2026:

- Ubuntu 24.04.1 LTS under WSL2
- x86-64
- GCC/G++ 13.3.0
- Intel Core i9-13900H
- AVX and AVX2 CPU support reported
- Valgrind 3.22.0 available
- GNU `/usr/bin/time` available

`perf` is not currently available for the installed WSL2 kernel. Final performance-counter experiments will therefore require a Linux environment where `perf` is verified to work.

## Status

Project setup, deterministic synthetic raster generation, scalar row-major smoothing, and alternate column-major smoothing are implemented.

Current verified functionality:

- basic project build
- deterministic synthetic raster generation
- raster dimension and reproducibility checks
- scalar row-major 3x3 average smoothing
- column-major 3x3 average smoothing
- identical border policy for both smoothing implementations
- column-major output verified against the row-major baseline
- hand-created smoothing correctness tests
- generated-raster equivalence test
- small rasters with no interior cells remain unchanged
- `make test` workflow
- Valgrind checks with no reported memory errors or leaks

The two smoothing implementations currently differ in traversal order, but no performance or cache-locality conclusion has been measured yet.

Threshold-classification, SIMD, benchmark, compiler-optimization, assembly-analysis, and performance experiments have not been completed yet.

No benchmark results have been collected yet.
